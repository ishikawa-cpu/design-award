# 宮工房 Design Award — セットアップ手順（ログイン不要版）

月例デザインアワード（エントリー → 投票 → 集計 → 発表）のWebアプリです。

- 画面は **GitHub Pages** で公開します。
- データと写真は **Supabase** に保存します。
- **ログインは不要**です。URLを開いて名前を入れれば、誰でもエントリーと投票ができます。
- **管理（締切・集計・発表）** は、画面下の「管理者の方はこちら」から管理者パスワードを入れた人だけができます。

**「あなたの操作」** と書いてある所は、管理者本人にしかできない操作です（アカウントやパスワードが関わるため）。

---

## 0. ファイルの中身

| ファイル | 役割 |
|---|---|
| `index.html` / `styles.css` / `app.js` | 画面（図面スタイル、発表モード含む） |
| `backend.js` | Supabase とのやり取り（設定が空なら仮データの「デモモード」で動く） |
| `config.js` | **接続先の設定**。Supabase の URL と anon キーを書く |
| `supabase/schema.sql` | データベースの設計図。Supabase の SQL Editor に貼り付けて実行する |
| `manifest.webmanifest` / `sw.js` / `icons/` | ホーム画面にアプリとして追加するためのもの |

## 1. Supabase のプロジェクトを作る（あなたの操作）— 済

- プロジェクト名 `design-award`、地域は Northeast Asia (Tokyo)、Free プランで作成済みです。

## 2. データベースを作る（最新版を実行し直す）

1. 左のメニューから **SQL Editor** を開き、入力欄を空にします。
2. `supabase/schema.sql` の中身を全部貼り付けて **Run** を押します。
   - 「destructive operation」の確認が出たら「Run query」を押して大丈夫です。
   - 何度実行しても壊れないように書いてあります。前に一度実行していても問題ありません。
3. 「Success. No rows returned」と出れば成功です。

## 3. 管理者パスワードを決める（あなたの操作）

1. SQL Editor の入力欄を空にして、次の1行を入れます。`好きなパスワード` の部分を、自分で決めたパスワード（8文字以上）に書き換えてください。
   ```sql
   select public.set_admin_password('好きなパスワード');
   ```
2. **Run** を押します。
3. 実行したら、入力欄のパスワードは消しておきます。保存（Save）はしないでください。

- データベースにはパスワードそのものは残らず、元に戻せない形（ハッシュ）だけが保存されます。
- パスワードを変えたいときは、同じ1行をもう一度実行します。変えた時点で、管理者モードの人は全員解除されます。
- 失敗が15分間に10回続くと、15分間ロックされます（総当たり対策）。

## 4. 匿名ログインを有効にする（あなたの操作）

アプリを開いた端末ごとに、目に見えないIDを自動で発行する仕組みです。これで「自分のエントリーには投票できない」「1人1票」を守ります。

1. **Authentication → Sign In / Providers** を開きます。
2. **「Allow anonymous sign-ins」** を ON にして Save します。
3. **Authentication → Rate Limits** を開き、**「anonymous sign-ins」の上限を 100 / 時間** くらいに上げて Save します。
   - 初期値は「同じネット回線から1時間30人まで」です。社内Wi-Fiから全員が一斉に開くと止まることがあるためです。

## 5. config.js を書き換える

Supabase の **Project Settings → API Keys**（または上部の「Connect」ボタン）に表示されている **anon / public** キーを、`config.js` に貼り付けます。URL は記入済みです。

```js
SUPABASE_URL: "https://ernsvrytqysofxkculqp.supabase.co",
SUPABASE_ANON_KEY: "eyJhbGciOi...（長い文字列）",
```

- `anon` キーは公開しても大丈夫な鍵です。（記入済み）
- **`service_role`（secret）キーは絶対に貼らないでください。**

## 6. GitHub Pages で公開する（あなたの操作）

1. GitHub で新しいリポジトリを作ります（例: `design-award`）。
   - 無料プランでは **Public** にする必要があります。
   - 公開されるのはプログラムだけです。写真や投票データは Supabase 側にあります。
2. このフォルダの中身を全部アップロードします（「Add file → Upload files」にドラッグ＆ドロップ）。
3. **Settings → Pages** を開き、Source: `Deploy from a branch`、Branch: `main` / `/ (root)` を選んで Save します。
4. 1〜2分待つと、`https://<GitHubのユーザー名>.github.io/design-award/` で開けるようになります。

## 7. 使いはじめる

1. 公開URLを開いて、名前を入れます。
2. 画面下の **「管理者の方はこちら」** → 管理者パスワードを入れると、「管理」タブが出ます。
3. 「管理」タブで今月の回を作ると、エントリーの受付が始まります。
4. URLを社内に共有します。スマホのホーム画面に追加すると、アイコンから開くアプリになります。
   - iPhone（Safari）: 共有ボタン（□↑）→「ホーム画面に追加」
   - Android（Chrome）: 右上の「⋮」→「ホーム画面に追加」

## 仕組みと注意点

- **だれでも使える**: URLを知っている人は、社外の人でもエントリー・投票・写真の閲覧ができます。URLは社内だけで共有してください。
- **1人1票は「端末ごと」**: ログインがないため、本人確認はしていません。
  - スマホとPCの両方で開くと、別の人として扱われます。エントリーした端末と違う端末からなら、自分の物件に投票できてしまいます。
  - ブラウザの履歴（サイトデータ）を消すと、新しい人として扱われます。
  - 社内の信頼関係が前提の仕組みです。
- **匿名投票**: 票（`ballots`）には投票者の情報を入れていません。管理者も、誰がどこに入れたかは見られません。表示されるのは「投票したかどうか」だけです。
  - ただし Supabase のダッシュボードに入れる人（プロジェクトのオーナー）は、技術的にはデータベースを直接見られます。
- **結果の公開範囲**: 集計結果は、管理者には集計直後から、ほかの人には「結果発表」を押した後だけ見えます。
- **写真**: 非公開の保存場所（`photos` バケット）に置き、12時間だけ有効なURLで表示します。長辺2400pxまで縮小しますが、トリミングはしないので縦横比はそのままです。
- **無料枠の目安**: 写真の保存は1GBまでです（1枚およそ0.5MB → 約2,000枚）。
- **デモモード**: `config.js` の anon キーが空のとき、または URL の末尾に `?demo` を付けたときは、仮データで動きます（保存はされません）。
  - `?demo=new` で名前入力の画面から始まります。
  - デモの管理者パスワードは `demo1234` です。
- **更新**: ファイルを直したら、GitHub に上書きでアップロードするだけで反映されます。
